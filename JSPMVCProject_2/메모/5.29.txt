<% BoardModel model = new BoardModel();
model.boardDelete(request, response); %> 
=> 이거 대신 controller 쓰는 거 mvc에서
     그럼 자바 코드도 싹 사라짐

mvc에서는 구조를 익히는게 포인트
=>
1. 주문을 받는다 : 요청
2. 주문에 해당되는 model 클래스 = 메소드 찾기
3. 요청 처리 => model이 가지고 있는 메소드 호출
4. jsp를 찾는다
5. reqest나 session에 결과값을 담아서 보낸다

컨트롤러클래스가 요청값을 읽는 곳 -> 대신 servlet 파일로 만든다
모델 패키지 속 클래스들은 요청값 읽지 못해서 따로 만들어줘야해 컨트롤러를  => 여긴 그냥 자바 클래스
그리고 mvc에서는 view - jsp파일을 만들면 그거에 해당하는 자바 클래스도 똑같이 만들어준다

실행은 컨트롤러 파일에서 실행한다 -> forward() 어쩌구
뷰폴더가 실행하는 폴더래
모델클래스는 독립되면 안 됨 => 인터페이스를 이용해 하나로 만듦 그래야 if문 없이 만들 수 있따

클래스에 인터페이스 연결하는 방법은 먼저 인터페이스를 만들고 
클래스를 만들어 그런다음 add 눌러 - 검색창에 model 검색하고 인터페이스 파일을 선택해주면 인터페이스 연결이 됨


전체적으로는 동일한데 실행하는 컨트롤럴 파일만 달라질거야
